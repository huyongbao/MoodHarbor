一、判定链：改造后的完整流程

1
用户语音 / 文本输入
H5 录音 → 16k WAV → 上传 → FunASR 转写（演示主链路为语音）
↓
2
关键词规则引擎（新增，代码执行）
加载 risk_keywords.json 四级词库，文本归一化后匹配。
命中一级词 → hit_level=1（一票否决标记）；命中二级词 → floor_level=2；三级词仅记录不强制定级；四级词只做频率统计。
↓
3
DeepSeek 大模型判定（prompt 注入词库上下文）
输出扩展为 { replyText, riskLevel, confidence, reason, matchedKeyword, semanticEquivalent }。
semanticEquivalent = 是否与一级词语义相同（含谐音 / 拆字 / 比喻 / 场景化表达），由模型识别。
↓
4
等级融合（代码强制）
hit_level==1 或 semanticEquivalent → 强制 1 级（无视模型结论）；
否则 floor_level==2 → min(模型等级, 2)；再叠加已有的矛盾提升（表情/语音高痛苦）与趋势提升（近 3 轮 ≤3）。
↓
5
处置动作（代码按等级强制执行，不依赖模型自觉）
话术要求 + 热线选择 + 工单生成，全部按《新就业心理关键词和援助热线》分等级映射（见第四节）。
↓
6
落库 + 异步记忆总结
消息落库后，后台任务调用 LLM 抽取本轮值得记的 1 条（fact / emotion / risk），写入 memories（新增 kind / importance 字段），不阻塞对话返回。

二、词库落库：risk_keywords.json

赛题文档的四类关键词整理为结构化配置，随代码分发（黑客松阶段零依赖，不进数据库）：

backend/config/risk_keywords.json { "version": "2026-10-17", "levels": { "1": [ // 一级：代码一票否决 + 进 prompt { "category": "直接自杀意念", "words": ["想死","不想活了","自杀","寻死","去死","不想活","活不下去","死了算了","结束这一切","一了百了"] }, { "category": "自杀计划与方式", "words": ["跳楼","跳桥","跳河","割腕","割脉","上吊","吃安眠药","烧炭","怎么死"] }, { "category": "告别与遗言", "words": ["遗书","遗言","最后一条消息","永别了","再见了","谢谢你们照顾我"] }, { "category": "自我否定与绝望", "words": ["活着没意思","活着就是拖累","我不配活着","没有人会在乎我死","消失算了"] }, { "category": "极端表述", "words": ["一起死","杀了自己","解脱了","再也不见了"] } ], "2": [ // 二级：floor_level=2 + 进 prompt { "category": "绝望感", "words": ["没希望了","看不到出路","没有意义","撑不下去了","熬不过去","一切都完了"] }, { "category": "强烈痛苦", "words": ["崩溃了","受不了了","快要疯了","生不如死","太痛苦了"] }, { "category": "自我价值否定", "words": ["我是废物","活着就是累赘","什么都做不好","没有用","不值得"] }, { "category": "睡眠饮食紊乱", "words": ["整夜睡不着","已经好几天没睡了","吃不下饭","完全没胃口"] }, { "category": "社会隔绝", "words": ["没有一个人理解我","不想跟任何人说话","把自己关起来","消失一段时间"] }, { "category": "物质滥用倾向", "words": ["靠喝酒才能睡","不吃药睡不着","想用什么东西麻痹自己"] }, { "category": "暗示性表达", "words": ["如果我出了什么事","以后你们不用管我了"] } ], "3": [ // 三级：只进 prompt 做类别提示，不参与强制定级 { "category": "焦虑与担忧", "hint": "压力大/焦虑/担心/害怕/紧张" }, { "category": "抑郁情绪", "hint": "不开心/低落/提不起精神" }, { "category": "愤怒与委屈", "hint": "太委屈/不公平/气死了/被欺负" }, { "category": "孤独感", "hint": "没人说话/太孤单/想找人聊聊" }, { "category": "职业倦怠", "hint": "不想跑了/干不下去了/想换工作" }, { "category": "现实压力", "hint": "被罚款/差评多/收入低/交不起房租" } ] } }

四级词（烦 / 累 / 无语 / 倒霉…）不进词库也不进 prompt——它们就是日常聊天，模型自由回应即是四级，强行标注反而引发锚定误判。四级只保留一个功能：24 小时内命中频率统计，同一用户显著上升时在管理端提示关注（对应文档"长期监测"要求）。

骑手场景化表达怎么办？文档每级都列了 5 条场景话术（如"这个月再被扣钱我就去死"）。这些不进代码规则（子串匹配命中率低、且"送完这单就不干了"这种不含标准词），而是全部写进 prompt 的"场景化理解"示例区，让模型学会这类表达模式——这正是"语义相同"判断的主战场。

三、大模型 Prompt 与输出改造

3.1 SYSTEM_PROMPT 新增三个区块

  • 词库区：一级 + 二级逐条列出（按类别分组），三级只列类别与示例。末尾加一句："注意识别谐音、拼音、拆字、比喻、场景化隐喻等变形表达。"
  • 语义等价判断区：要求模型对每轮输出 semanticEquivalent（是否与一级词语义相同）和 matchedKeyword（命中或语义对应的词），作为留痕依据。
  • 回复风格区：普通聊天（四级）放开约束——不再强制"3 句以内"，允许自然对话；一/二/三级仍按文档话术要求（共情、不追问细节、不说教、先安抚后转介）。

3.2 generate_reply 输出扩展

{ "replyText": "…", "riskLevel": 1, "confidence": 0.96, "reason": "…", "matchedKeyword": "遗书", // 新增：命中词 / 语义对应词，无则 null "semanticEquivalent": false // 新增：是否与一级词语义相同 }

matchedKeyword 写入 RiskEvaluation.reason 留痕——评委问"为什么判一级"，答案不是"模型说的"，而是"命中'遗书'（告别与遗言类）+ 模型确认语义等价"。可解释、可审计。

3.3 融合逻辑（miniprogram.py）

# 第2步之后插入： kw = match_keywords(text) # 代码规则，先行 result = await generate_reply(text, context_summary, keywords_ctx) final_level = result["riskLevel"] if kw["hit_level"] == 1 or result.get("semanticEquivalent"): final_level = 1 # 一票否决 elif kw["floor_level"] == 2: final_level = min(final_level, 2) # 保底二级 # 之后接已有的矛盾提升 / 趋势提升（不变）

五、四个遗留问题的落地方案

5.1 打招呼带记忆（你已确认：不作限制，按事实提）

  • 新增 GET /api/v1/greeting：读本人最近 10 条记忆 → 优先取 kind=fact 条目 → DeepSeek 生成一句自然问候（带 2s 超时，失败回退现有固定文案）。
  • H5 fireGreet() 改异步：SDK 在线后先请求问候语，请求未返回前不打招呼；与 5s 兜底定时器加互斥锁防重复。
  • 措辞软化（建议而非限制）：prompt 要求提及往事时用概括性关怀（"上次你提到家里的事，现在好些了吗"），不逐字引用原话——这不是限制你"不提"，而是让问候听起来自然，评委观感更好。是否采纳由你定。

5.2 每轮结束记忆总结（你已确认）

  • memories 表加 kind（fact/emotion/risk）+ importance（high/mid/low）字段（SQLite ALTER TABLE，启动时迁移）。
  • 对话返回后 asyncio.create_task 后台抽取：本轮 user+ai 内容 → LLM 判断"有没有值得长期记住的事"→ 有则写 1 条（无则跳过），替换现在"每轮无脑写摘要"的逻辑。空内容 / 纯语气词不写。
  • 抽取失败静默跳过（不影响主对话），打日志。

5.3 高危引导拨号（你已确认：按文档分等级）

即第四节映射表，落到 build_intervention + H5 热线卡两处：热线按等级选号，12356 变成可点按钮，一级卡片追加 110/120 文案。

5.4 演示用语音

  • 链路本身已通（H5 录音 → FunASR），但库里有 3 条 [语音/表情] 空转写记录——演示前必须真机彩排语音，确认 asrText 有值。
  • 排查方向：上传音频的采样率/编码是否符合 FunASR 预期；H5 录音时长过短被 VAD 切掉。
  • 兜底：演示机提前授权摄像头/麦克风，避免现场弹权限框。
