演示的骨架都在：进页面、聊天、分级、弹窗、工单。
但记忆这条主线只实现了"存"，没实现"用"和"筛"。
你设想的第 2 步是整个演示最出彩的地方，恰恰是唯一一个完全没有代码支撑的环节。

逐步骤详解

1
进入页面 —— 点首页按钮，进数字人聊天页
支持

首页「我想聊聊」→ pages/talk → 建会话 → 取 H5 地址 → web-view 加载 → 星云 SDK 唤醒 → 打招呼。整条链路完整。

唯一隐患：数字人地址被全局缓存，切换陪伴者不刷新

// talk.js:54-57 if (app.globalData.dhUrl) { this.setData({ configured: true, dhUrl: build(app.globalData.dhUrl) }); return; // ← 直接复用上次 URL，不重新请求 }
彩排时先用小满进过一次，再改选知远，第二次进页面名字和形象还是小满。
演示前杀掉小程序重进，或在 app.js 里把 dhUrl 置空。彻底修 15 分钟。
2
读记忆并打招呼 —— 记忆里有「母亲生病」就问母亲身体
完全不支持

这是最大的缺口。现有代码里没有任何一条路径能实现"记忆驱动的问候"。

五个断点

#断点代码证据
1打招呼文案是硬编码常量index.html:545 GREET_TEXT = "准备好了就开口，我一直在听。"
2打招呼在 SDK 在线回调里，不发后端请求index.html:737-748 onStatusChange(0) → fireGreet()
3后端没有打招呼接口miniprogram.py:391 /digital-human/view 只返回 URL
4记忆检索只在 /chat/completions 内部miniprogram.py:188
5记忆里没有结构化事实memory_service.py:47 整句截断 120 字

即使把记忆拼给模型，也拿不到"母亲生病"

【1】对吧？我就按照说说话，今天有点累。（情绪：愤怒焦虑，风险3级） 【2】辛苦了，忙了一天还记得来说说话…（情绪：平稳，风险4级） ↑ 存的是原话片段，不是抽取后的事实
要补四件事
① 记忆表加 kind（fact/emotion/risk）+ importance
② 新增 GET /api/v1/greeting：挑 fact 类记忆 → LLM 生成问候 → 2s 超时回退固定文案
③ H5 fireGreet() 改异步取问候，处理与 5s 兜底定时器的竞争
④ 预置一条"母亲住院"的演示记忆（否则没东西可说）
需要产品拍板：打招呼该不该提风险事件？如果记忆里是"我写好遗书了"，一上来就问这是二次伤害。
建议：kind=risk 的记忆永远不在问候中提及，只提中性事实（家人健康、工作变动、养的宠物）。

工作量：约 5 小时（表结构 1h + 接口 2h + H5 1.5h + 演示数据 0.5h）

3
正常聊天 —— 回复由大模型生成
部分支持

~~硬阻断：欠费~~ ✅ 已于 20:50 解决

// 变更前：第三方中转 glm-5.3，余额不足 POST /v1/chat/completions → HTTP 403 {"error":{"message":"token quota is not enough, remain ＄0.003526"}} // 变更后：DeepSeek 官方 API LLM_BASE_URL=https://api.deepseek.com/v1 LLM_MODEL=deepseek-flash

5 条标准用例全部命中预期等级，全部走真实 LLM，延迟 1.2~2.4s：

用例预期实测耗时
今天跑了三十单，累是累，但收入还行4✅ 41.7s
今天又被客户投诉了，气死我了3✅ 32.0s
这日子没法过了，活着真没意思2✅ 22.0s
我已经写好遗书了，不想活了1✅ 12.4s
切换时顺带修掉一个隐藏 bug：max_tokens=300 对推理模型是边界值——思考 token 随机占 100~180，加上 JSON 正文偶尔超预算被截断（finish_reason=length），导致高危语句误落规则兜底。已提到 1024。

软阻断：多轮聊天仍会露馅

问题后果
没有多轮上下文messages 只有「人设 + 趋势摘要 + 本轮」。你说"我妈住院了"，下一句"手术做了吗"，它反问"谁住院了？"
人设没注入DigitalHuman.prompt 存了但没人读，小满和知远话术一模一样
回复限制太紧3 句以内 + 强制 JSON，适合"疏导"不适合"聊天"
"正常聊天"是多轮演示的核心。没有 history，多轮就是假的——这是评委最容易当场识破的点。

工作量：加 history + 注入人设 2 小时（模型通道已就绪）。

4
敏感词分级 + 高危引导热线
部分支持

分级链路本身完整：四级映射、1/2 级建工单、2→1 自动升级、三级留痕、H5 热线卡 + 遮罩。但对照你给的文档，有 4 个缺口。

缺口 1 · 规则兜底在高置信度时不生效（安全漏洞）

// llm_provider.py:91-95 if confidence < RISK_CONFIDENCE_THRESHOLD: // 只有 <0.8 才跑规则 fb_level, fb_reply, _ = rule_fallback(user_text)
模型返回 riskLevel=4, confidence=0.95，而文本里明写着"我写好遗书了"——规则完全不介入。
文档承诺"防漏报"，代码在高置信度漏判时没有任何安全网。
更微妙的是：之前欠费期间全走规则兜底，这个漏洞被完全掩盖；现在恢复真实 LLM，漏洞会直接暴露——这正是必须优先修的原因。
规则命中 1 级时无条件覆盖模型结果，不看置信度。

缺口 2 · 一级回复不强制植入热线话术

文档写"数字人回复即时植入 12356 转介话术"，但 SYSTEM_PROMPT 里没有这条硬约束，replyText 由模型自由发挥。H5 热线卡是另一条通道，所以视觉上有兜底，但"数字人亲口说出来"不保证。

缺口 3 · 敏感词表太薄

(1, ["遗书", "跳下去", "自杀", "不想活", "轻生", "从桥上"]) ← 6 个词 (2, ["没意思", "撑不住", "熬不下去", "崩溃", "绝望", "没合眼", "没法过"]) (3, ["气死", "投诉", "罚款", "委屈", "白跑", "误解", "累"])

骑手真实语境里大量高危表达没覆盖："一了百了""撞死算了""活着没意义""不想醒过来""解脱""把孩子托付给"。

缺口 4 · 12356 不可点，只能拨宁师傅

<div class="hotline-phone">025-96889910</div> ← 可点击拨打 <div class="hotline-lead">…24 小时心理支持热线 12356…</div> ← 纯文本，点不了
如果演示话术说"请拨打 12356"，观众会发现点不了。

工作量：规则加固 + 词表 2h；1 级话术强制 1h；12356 按钮 0.5h。

5
写入记忆 —— 把多轮对话中值得记的内容沉淀
语义不符

你说的是"把多轮对话中值得记忆的内容写入"，现有实现是"每一轮都写一条"。

// miniprogram.py:244，每轮对话结束无条件执行 memory_service.add(db, user_id, conv_id, text, result["riskLevel"])
你的设想现状
对话结束后总结，抽 1-3 条值得记的每轮写 1 条，5 轮 = 5 条
抽出事实（"母亲住院"）存整句截断 120 字
有"值不值得记"的判断无，连"嗯""好的"都会写进去
有会话结束的触发点没有 /conversations/{id}/close 接口
库里 61 条记忆有多条 content 为空（语音转写失败仍写入），也有大量"今天有点累"这类噪音。
如果第 2 步接上记忆，这些噪音会直接污染问候语。

两条可选路线

路线做法工时
A · 会话结束总结
推荐，贴合你的设想		 POST /conversations/{id}/close → 取全会话 → LLM 抽 1-3 条事实/重要情绪 → 写入带 kind/importance → 返回"已记住：母亲住院" 4h
B · 每轮写 + 过滤
省事		 保留每轮写，但长度 <5 字 / 纯语气词 / 空内容不写 1h
演示需要可见反馈：现在写记忆是纯后台行为，观众看不到。建议管理端记忆页加"本次会话新增"标记，或小程序端结束时提示"这次聊的我都记住了"。

三个不修必翻车的隐藏坑

坑 1 · 测试数据污染

固定 openid wx_dev_demo，库里已有 61 条记忆、136 个会话。第 2 步接上记忆后，数字人可能读到彩排残留。

演示前跑一次 DELETE /api/v1/conversations/all，再手工预置演示记忆。

坑 2 · 语音转写出空

最近 3 条用户消息是 [语音/表情] 占位符，说明那几次 ASR 返回空文本。演示用语音会出现"答非所问"。

更麻烦的是：小程序端目前没有文字输入入口，只有 H5 语音。如果语音不稳定，没有退路。

坑 3 · LLM 阶段纯静默

松手到开口 = ASR → LLM → TTS 串行，3-6 秒。H5 只显示"正在听你说…"，LLM 那 2-4 秒全场安静。

加一句"正在想…"中间态字幕，或做流式返回 + 分段口播。

需要你们拍板的 4 个问题

1. 打招呼提不提风险事件？
建议只提中性事实，kind=risk 的记忆永不在问候中提及。
2. 高危引导拨哪个号？
文档写 12356，界面只有宁师傅（025-96889910）可点。统一成哪个？
3. 记忆是"每轮写"还是"会话结束总结"？
前者省 3 小时，后者更贴合你的设想、也更好讲。
4. 演示用语音还是打字？
语音更有冲击力但 ASR 不稳定，且小程序端没有文字输入入口。要打字得先加输入框（约 2h）。
